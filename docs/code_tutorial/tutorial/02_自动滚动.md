# 第 02 章：自动滚动到底部（steps/step02_scroll.py）

## 本步目标

上一章里，每次发消息我们都要手动调一次 `scroll_end()` 才滚到底。本章把滚动行为改成「锚定」：一旦锚定底部，之后任何新消息进来滚动区都会自动跟着滚；而你手动往上翻看历史时，锚定自动解除，不会被新消息打断阅读。同时修掉 Textual `anchor()` 的一个小 bug（第一条消息后内容整体下移、顶部空白）。

和第 01 步的区别：滚动区从 `VerticalScroll` 换成自定义的 `ChatScroll`，`scroll_end()` 换成 `anchor()`。

## 新概念

- **anchor()**：`scroll_end()` 是「现在立刻滚到底部」，滚一次就完事；`anchor()` 是「从现在起一直吸在底部」——内容一增多就自动跟随，用户向上滚就自动解除，滚回底部附近又重新锚定。这正是聊天软件想要的滚动行为。
- **reactive（响应式属性）**：Textual 组件上有一类特殊属性，赋值时会自动触发界面刷新，比如 `scroll_y`（当前滚动位置）。`set_reactive()` 是绕过校验、直接给 reactive 赋值的内部方法。
- **继承容器做子类**：`ChatScroll` 继承 `VerticalScroll`，只覆盖一个 `set_reactive` 方法，其余行为原封不动。这是本教程反复使用的套路——不用改 Textual 源码，在子类里把不想要的行为挡回去。
- **run_test(size=(w, h))**：测试时可以指定虚拟终端的窗口大小。用小窗口能轻松制造「内容超屏」，用大窗口能验证「内容不足一屏」的场景。

## 动手实现

在上一章 `steps/step01_basic.py` 的基础上改，一共两处增量。

### 1. 新增 ChatScroll 类

在 import 之后、`ChatApp` 之前加上这个类（注意 import 里新增一行 `from textual.widget import Widget`）：

```python
class ChatScroll(VerticalScroll):
    """聊天滚动区：修复 anchor() 的一个小 bug。

    anchor() 让滚动区一直吸底；但 Textual 的合成器在「内容不足一屏」时
    会把 scroll_y 直接设成负数（set_reactive 绕过了 0 下限的校验），表现为：
    第一次发消息后，上面的内容整体往下挪、顶部空出一片。
    这里把负的滚动值挡回去即可。
    """

    def set_reactive(self, reactive, value) -> None:
        if (
            isinstance(value, (int, float))
            and value < 0
            and (reactive is Widget.scroll_y or reactive is Widget.scroll_target_y)
        ):
            value = 0
        super().set_reactive(reactive, value)
```

逐段讲解：

- `set_reactive(reactive, value)` 是框架内部给 reactive 属性直接赋值的入口。`reactive` 参数是「要改哪个属性」，`value` 是新值。
- `if` 的三个条件合在一起：「赋值的是数字」「值是负数」「改的是 `scroll_y` 或 `scroll_target_y`（纵向滚动位置 / 滚动目标位置）」。
- 三条都满足就把值钳制到 0，然后交给 `super().set_reactive()` 走正常流程。其余情况一概放行，不影响正常滚动。

为什么需要它：Textual 的合成器在内容不足一屏时，会算出 `内容高度 - 可视高度` 这样一个负数，通过 `set_reactive` 直接写进 `scroll_y`，绕过了正常的 0 下限校验。结果就是你发第一条消息后，整个聊天内容往下挪、顶部空出一片。这个子类只挡负值，内容真超屏时 anchor 照常吸底。

### 2. compose() 里换掉滚动区

把上一章的：

```python
with VerticalScroll(id="chat-scroll"):
    pass
```

改成：

```python
with ChatScroll(id="chat-scroll"):
    pass
```

`id` 不变，所以 CSS 和后面 `query_one("#chat-scroll", ...)` 的代码都不用动。

### 3. 回车处理里把 scroll_end 换成 anchor

在上一章 `on_input_submitted` 的末尾，把：

```python
# 滚动到底部，让新消息可见
scroll.scroll_end(animate=False)
```

改成：

```python
# 锚定到底部：新消息进来时自动跟随滚动
scroll.anchor()
```

语义变化很关键：`anchor()` 调用一次就长期有效，之后这条滚动区再 `mount` 任何新消息都会自动滚到底，不需要每次发消息都重复调用（这里放在事件里每次调用一次也无妨，幂等）。

其余部分（CSS、`on_mount`、清空输入框、挂两条消息）和上一章完全一样。

## 完整代码

下面是 `steps/step02_scroll.py` 的完整源码，和仓库里的文件逐字一致，可以直接 `python steps/step02_scroll.py` 运行对照：

```python
"""第 2 步：消息多到超出屏幕后，让滚动区自动跟着新消息滚到底。

学到什么：
- scroll_end(animate=False)：一次性滚到底部（第 1 步用的就是它）。
- anchor()：「锚定」底部——之后每次有新消息进来都会自动跟着滚；
  用户手动上翻时锚定会自动解除，不打断阅读，回到底部附近又重新锚定。
- ChatScroll：anchor() 有个小 bug——内容不足一屏时，框架会把滚动位置
  设成负数（内容整体下移、顶部空白）。这个子类把负值挡回去。
  后面每一步的滚动区都用它。

和第 1 步的区别：scroll_end 换成 anchor，滚动区换成 ChatScroll。
"""

from textual.app import App, ComposeResult
from textual.widget import Widget
from textual.containers import VerticalScroll
from textual.widgets import Input, Static


class ChatScroll(VerticalScroll):
    """聊天滚动区：修复 anchor() 的一个小 bug。

    anchor() 让滚动区一直吸底；但 Textual 的合成器在「内容不足一屏」时
    会把 scroll_y 直接设成负数（set_reactive 绕过了 0 下限的校验），表现为：
    第一次发消息后，上面的内容整体往下挪、顶部空出一片。
    这里把负的滚动值挡回去即可。
    """

    def set_reactive(self, reactive, value) -> None:
        if (
            isinstance(value, (int, float))
            and value < 0
            and (reactive is Widget.scroll_y or reactive is Widget.scroll_target_y)
        ):
            value = 0
        super().set_reactive(reactive, value)


class ChatApp(App):
    CSS = """
    Screen {
        layout: vertical;
    }
    #chat-scroll {
        width: 1fr;
        height: 1fr;
        padding: 1 2;
    }
    #user-input {
        dock: bottom;
        height: auto;
        padding: 1 2;
    }
    """

    def compose(self) -> ComposeResult:
        with ChatScroll(id="chat-scroll"):
            pass
        yield Input(placeholder="输入问题，按 Enter 发送", id="user-input")

    def on_mount(self) -> None:
        """启动后自动聚焦输入框。"""
        self.query_one("#user-input", Input).focus()

    async def on_input_submitted(self, event: Input.Submitted) -> None:
        user_text = event.value.strip()
        if not user_text:
            return

        self.query_one("#user-input", Input).value = ""

        scroll = self.query_one("#chat-scroll", VerticalScroll)
        await scroll.mount(Static(f"你: {user_text}"))
        await scroll.mount(Static("AI: 收到！"))

        # 锚定到底部：新消息进来时自动跟随滚动
        scroll.anchor()


if __name__ == "__main__":
    app = ChatApp()
    app.run()
```

## 运行与验证

确保已按第 01 章装好环境，然后：

```bash
python steps/step02_scroll.py
```

动手验证：

- 发第一条消息，注意顶部：内容应该贴顶显示，不会整体下移。可以把 `ChatScroll` 临时换回 `VerticalScroll` 再跑一次对比——会看到第一条消息后顶部空出一片。
- 连发十几条消息直到出现滚动条：每发一条，视图自动停在最底部，不用手动滚。
- 用鼠标滚轮或 `↑` 键（先点一下聊天区把焦点移过去）向上翻，再发一条新消息：视图不会被拽回底部，说明锚定已解除；手动滚回最底部附近，锚定又会恢复。

这三条手动验证分别对应两个方向的检查：

1. 小窗口连发多条消息：内容超屏后（出现滚动条），视图始终停在底部，说明 `anchor()` 的自动吸底生效。
2. 大窗口只发一条消息：内容贴顶显示、顶部不会空出一片，说明 `ChatScroll` 挡住了负的 `scroll_y`，首条消息不下移。

## 常见问题

- **第一条消息后内容整体下移、顶部空一片？** 就是本章要修的 bug：你在用裸的 `VerticalScroll` 配 `anchor()`。换成 `ChatScroll` 即可，原理见上文——合成器在内容不足一屏时通过 `set_reactive` 写入了负的 `scroll_y`。
- **anchor 之后向上翻，还是被弹回底部？** 说明你在每次新消息到达时又重新调用了 `anchor()`，把用户解除的锚定又装回去了。本项目里「每次发消息都 anchor 一次」是可接受的（用户消息本身就该把视图带到底部），但如果你做纯日志窗口，应该只在初始时 anchor 一次。
- **测试里 `scroll_y` 读到的值和预期差一点？** 布局是异步的。`pilot.press(...)` 之后记得 `await pilot.pause(0.2)` 之类的等待，让 Textual 完成布局和滚动更新再断言。

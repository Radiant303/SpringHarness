# 第 03 章：自定义消息组件（steps/step03_widgets.py）

## 本步目标

前两章里，消息是光秃秃的 `Static(f"你: {text}")` 字符串，用户消息和 AI 回复长得一模一样。本章把消息升级成两个自定义组件：`UserMessage` 带黄色 `✨` 前缀，`AssistantMessage` 带灰色 `●` 圆点前缀，各自带样式。聊天区一眼就能分清谁在说话。

和第 02 步的区别：挂进滚动区的不再是裸 `Static`，而是两个带 `DEFAULT_CSS` 和彩色前缀的自定义组件。滚动、输入框、事件处理完全不变。

## 新概念

- **继承 Static 写自己的组件**：`Static` 是最简单的显示组件，给它一个文本它就显示出来。继承它，在 `__init__` 里加工一下文本再交给 `super().__init__()`，就有了你自己的消息组件。后面 Markdown 消息、思考行都是这个思路的延伸。
- **DEFAULT_CSS**：写在组件类里的样式表，跟着组件走。好处是「组件长什么样」由组件自己说了算，App 不用关心；任何界面挂上 `UserMessage`，样式自动生效。
- **Text.assemble**：Rich 库的富文本工具。`Text.assemble(("✨ ", "yellow"), (text, ""))` 把若干段 `(文字, 样式)` 拼成一整段——前缀是黄色，正文用默认颜色。Textual 底层用 Rich 渲染文本，所以 `Static` 直接接受 `Text` 对象。
- **CJKStatic**：本步 `UserMessage` 实际继承的是 `steps/cjk_wrap.py` 里的 `CJKStatic`，而不是裸 `Static`。它是「中文友好换行版 Static」：Textual 默认按空格分词换行，一段没有空格的中文会被当成一个超长的词，写到一半就整段挪到下一行，右侧空一大片；`CJKStatic` 允许任意两个汉字之间断行，修复这个问题。这一步只需把它当成 Static 用，原理到第 07 章细讲。

## 动手实现

### 1. 新增 import

文件顶部加上：

```python
from rich.text import Text

from cjk_wrap import CJKStatic
```

`Text` 用来拼彩色富文本；`CJKStatic` 是 `UserMessage` 的基类。

### 2. 写两个消息组件

```python
class UserMessage(CJKStatic):
    """用户消息：✨ 黄色前缀。"""

    DEFAULT_CSS = """
    UserMessage {
        width: 1fr;
        height: auto;
        margin-top: 1;
    }
    """

    def __init__(self, text: str, **kwargs) -> None:
        # Text.assemble 把多段（文字, 样式）拼成一段富文本
        content = Text.assemble(("✨ ", "yellow"), (text, ""))
        super().__init__(content, **kwargs)


class AssistantMessage(Static):
    """AI 消息：● 圆点前缀（这一步还是一条固定回复）。"""

    DEFAULT_CSS = """
    AssistantMessage {
        width: 1fr;
        height: auto;
    }
    """

    def __init__(self, text: str, **kwargs) -> None:
        content = Text.assemble(("● ", "#c8cdd5"), (text, ""))
        super().__init__(content, **kwargs)
```

逐点讲解：

- **`__init__` 的套路**：两个组件结构完全一样——先 `Text.assemble` 拼出「带样式的前缀 + 默认样式的正文」，再 `super().__init__(content, **kwargs)` 交给父类显示。`**kwargs` 原样透传，以后想给某条消息加 `id` 或 `classes` 不用改组件。
- **`Text.assemble(("✨ ", "yellow"), (text, ""))`**：第一段文字 `✨ ` 用 `yellow` 样式；第二段 `text` 用空字符串样式，即「不指定，用默认前景色」。注意前缀里带一个空格，负责和正文拉开距离。
- **颜色写法**：`yellow` 是命名颜色；`#c8cdd5` 是十六进制颜色（一种浅灰）。Rich 两种都认。
- **DEFAULT_CSS 里的选择器用类名**：`UserMessage { ... }` 选中所有 `UserMessage` 实例，不用给组件起 `id`。
- **三条样式**：`width: 1fr` 占满整行宽；`height: auto` 高度按内容（文字换行后有几行就多高）；`margin-top: 1` 只给了 `UserMessage`——每条用户消息上方空一行，把一轮问答和上一轮隔开，AI 回复紧贴用户消息，视觉上是一组。
- **为什么 UserMessage 用 CJKStatic 而 AssistantMessage 用 Static**：用户消息是纯粹的自然语言长文本，中文提前换行最明显；这一步的 AI 回复是写死的短句，先保持简单，第 04 步它会升级成 Markdown 容器，第 07 步统一换 CJK 方案。

### 3. 回车处理里换成新组件

在 `on_input_submitted` 里，把上一章的两行：

```python
await scroll.mount(Static(f"你: {user_text}"))
await scroll.mount(Static("AI: 收到！"))
```

改成：

```python
await scroll.mount(UserMessage(user_text))
await scroll.mount(AssistantMessage("收到！这就是自定义消息组件。"))
```

「你: 」这个文字前缀不再需要了——`✨` 图标加颜色本身就标明了身份。其余代码（清空输入框、`scroll.anchor()`）不变。

## 完整代码

下面是 `steps/step03_widgets.py` 的完整源码，和仓库里的文件逐字一致，可以直接 `python steps/step03_widgets.py` 运行对照：

```python
"""第 3 步：把消息做成自定义组件，加上 ✨ / ● 前缀和颜色。

学到什么：
- 继承 Static 写自己的组件（UserMessage / AssistantMessage）。
- DEFAULT_CSS：组件自带的样式，跟着组件走。
- Rich 的 Text.assemble：给同一段文字的不同部分上不同颜色。

和第 2 步的区别：消息不再是光秃秃的 Static 字符串，
而是有样式、有前缀图标的自定义组件。
"""

from rich.text import Text

from textual.app import App, ComposeResult
from textual.widget import Widget
from textual.containers import VerticalScroll
from textual.widgets import Input, Static

from cjk_wrap import CJKStatic


class UserMessage(CJKStatic):
    """用户消息：✨ 黄色前缀。"""

    DEFAULT_CSS = """
    UserMessage {
        width: 1fr;
        height: auto;
        margin-top: 1;
    }
    """

    def __init__(self, text: str, **kwargs) -> None:
        # Text.assemble 把多段（文字, 样式）拼成一段富文本
        content = Text.assemble(("✨ ", "yellow"), (text, ""))
        super().__init__(content, **kwargs)


class AssistantMessage(Static):
    """AI 消息：● 圆点前缀（这一步还是一条固定回复）。"""

    DEFAULT_CSS = """
    AssistantMessage {
        width: 1fr;
        height: auto;
    }
    """

    def __init__(self, text: str, **kwargs) -> None:
        content = Text.assemble(("● ", "#c8cdd5"), (text, ""))
        super().__init__(content, **kwargs)



class ChatScroll(VerticalScroll):
    """聊天滚动区：修复 anchor() 的一个小 bug。

    anchor() 让滚动区一直吸底；但 Textual 的合成器在「内容不足一屏」时
    会把 scroll_y 直接设成负数（set_reactive 绕过了 0 下限的校验），表现为：
    第一次发消息后，上面的内容整体往下挪、顶部空出一片。
    这里把负的滚动值挡回去即可。
    """

    def set_reactive(self, reactive, value) -> None:
        if (
            isinstance(value, (int, float))
            and value < 0
            and (reactive is Widget.scroll_y or reactive is Widget.scroll_target_y)
        ):
            value = 0
        super().set_reactive(reactive, value)


class ChatApp(App):
    CSS = """
    Screen {
        layout: vertical;
    }
    #chat-scroll {
        width: 1fr;
        height: 1fr;
        padding: 1 2;
    }
    #user-input {
        dock: bottom;
        height: auto;
        padding: 1 2;
    }
    """

    def compose(self) -> ComposeResult:
        with ChatScroll(id="chat-scroll"):
            pass
        yield Input(placeholder="输入问题，按 Enter 发送", id="user-input")

    def on_mount(self) -> None:
        """启动后自动聚焦输入框。"""
        self.query_one("#user-input", Input).focus()

    async def on_input_submitted(self, event: Input.Submitted) -> None:
        user_text = event.value.strip()
        if not user_text:
            return

        self.query_one("#user-input", Input).value = ""

        scroll = self.query_one("#chat-scroll", VerticalScroll)
        await scroll.mount(UserMessage(user_text))
        await scroll.mount(AssistantMessage("收到！这就是自定义消息组件。"))

        scroll.anchor()


if __name__ == "__main__":
    app = ChatApp()
    app.run()
```

## 常见问题

- **改了 DEFAULT_CSS 但没生效？** 先检查选择器：`DEFAULT_CSS` 里用类名（`UserMessage { }`），不是 `#id`。再检查是不是在 App 的 `CSS` 里又写了同名规则把它覆盖了——App 级 CSS 优先级高于组件的 `DEFAULT_CSS`。
- **文字能换行的地方不对，比如 `✨` 和正文被拆到两行？** `Text.assemble` 拼出来的仍是一整段文本，换行由渲染层按宽度决定。前缀和正文之间用普通空格相连，正常宽度下不会断开；如果终端极窄，那是任何文本都会遇到的正常折行。
- **自定义组件里忘了调 `super().__init__()`？** 组件不会被正确初始化，挂载时会报各种莫名其妙的错。继承 Textual 组件时，`super().__init__()` 必须调，而且要在设置任何组件属性之前调。

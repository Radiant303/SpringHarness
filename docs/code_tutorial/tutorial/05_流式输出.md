# 第 05 章：流式输出（一个字一个字往外蹦）

对应文件：`steps/step05_streaming.py`

## 本步目标

上一章回答是一次性整段出现的。本章让它像真实 AI 助手一样分片流出来：每 0.05 秒吐出 8 个字符，Markdown 边收边渲染。关键要求是流式期间界面不能卡——你还能继续打字、发下一条消息。

## 新概念

- **`Markdown.get_stream(md)`**：`Markdown` 组件可以先创建成空白的，再用这个类方法拿到一个「流写入器」。反复 `await stream.write(片段)` 往里追加内容，它会自动合并刷新节奏（不会每来一个字符就重绘一次，把终端刷爆）。用完必须 `await stream.stop()` 收尾。
- **`run_worker()`**：Textual 的后台任务机制，把一个协程丢到后台跑，立即返回。为什么这步必须有它？`on_input_submitted` 是消息处理函数，如果你在里面直接 `await` 整个流式循环，流没跑完之前，后续的按键消息都排不上队——表现就是「回答没吐完，键盘全失灵」。放进 worker 后，事件循环照常运转，界面一直是活的。
- **`stream-pending` 等待态**：一个自定义 CSS 类，`display: none` 把整行隐藏。回答的第一个字符到达前，先把「圆点 + 空回答」整行藏起来，避免屏幕上出现一个孤零零的 `●`；首片内容写入前再移除这个类，让行显示出来。
- **`asyncio.sleep()`**：本章用它模拟网络延迟。真实项目里这里换成 LLM API 的流式返回即可，结构不变。

## 动手实现

在上一章 `steps/step04_markdown.py` 的基础上改。`UserMessage`、`ChatScroll`、`ChatApp` 骨架不动，改三处：`AssistantMessage`、发送逻辑、新增 `stream_response` 方法。

### 1. `AssistantMessage`：创建空 Markdown，整行先藏起来

上一章 `compose()` 里是 `Markdown(ANSWER, id="answer-md")`——内容一步到位。现在改成空组件等流写入，同时给 `answer-row` 加上 `stream-pending` 类（`steps/step05_streaming.py:81`）：

```python
    def compose(self) -> ComposeResult:
        with HorizontalGroup(classes="answer-row stream-pending"):
            yield Static("●", classes="assistant-bullet")
            # 注意：这里不再传入 ANSWER，先创建一个空的 Markdown
            yield Markdown(id="answer-md")
```

CSS 里对应加一条规则（放在 `DEFAULT_CSS` 里）：

```css
    AssistantMessage .stream-pending {
        display: none;
    }
```

`display: none` 的组件不占布局、不绘制，就像不存在。首个 chunk 到达时移除这个类，行才出现。

### 2. 发送逻辑：mount 之后把流式任务丢到后台

`on_input_submitted` 末尾，上一章到 `scroll.anchor()` 就结束了。现在多一步：留住 `AssistantMessage` 的引用，启动后台 worker（`steps/step05_streaming.py:143`）：

```python
        scroll = self.query_one("#chat-scroll", VerticalScroll)
        await scroll.mount(UserMessage(user_text))
        message = AssistantMessage()
        await scroll.mount(message)

        scroll.anchor()

        # 流式输出放到后台 worker 里跑，界面不会被卡住
        self.run_worker(self.stream_response(message))
```

注意 `run_worker()` 接收的是一个协程对象（`self.stream_response(message)` 调用了但不 await），它会帮你调度到后台。这里**不要**写 `await self.stream_response(message)`——那就又堵死了。

### 3. 新增 `stream_response`：循环写片段

这是本步的核心方法，加在 `ChatApp` 里（`steps/step05_streaming.py:151`）：

```python
    async def stream_response(self, message: AssistantMessage) -> None:
        """模拟 AI 的流式回答：每 0.05 秒吐出 8 个字符。"""
        md = message.query_one("#answer-md", Markdown)
        answer_row = message.query_one(".answer-row")
        stream = Markdown.get_stream(md)
        try:
            for i in range(0, len(ANSWER), 8):
                if i == 0:
                    answer_row.remove_class("stream-pending")
                await stream.write(ANSWER[i : i + 8])
                await asyncio.sleep(0.05)
        finally:
            # 不管中途是否出错，都要把流停掉，否则后台任务不会退出
            await stream.stop()
```

逐段看：

- 前两行从刚挂载的消息里把 `Markdown` 组件和整行容器查出来。`query_one` 可以按 id（`#answer-md`）也可以按 class（`.answer-row`）查。
- `Markdown.get_stream(md)` 拿到流写入器。注意这是个类方法，参数是要写入的 `Markdown` 实例。
- 循环每次切 8 个字符：`i == 0`（第一片）写入前，先 `remove_class("stream-pending")` 让整行显示——这样圆点出现的那一刻，后面已经有内容了。
- `await stream.write(...)` 追加内容，`Markdown` 会按已经收到的部分重新解析渲染，所以你会看到代码块的高亮是逐渐成型的。
- `await asyncio.sleep(0.05)` 模拟网络间隔。真实项目里换成 `async for chunk in llm_stream:` 就行。
- `finally: await stream.stop()`：流必须收尾。中途出错也好、正常结束也好，`stop()` 让 `Markdown` 做最终定稿，也让后台任务干净退出。漏了它，worker 会一直挂着。

## 完整代码

下面是 `steps/step05_streaming.py` 的完整源码，和仓库里的文件逐字一致。你也可以直接运行仓库里的文件对照。

````python
"""第 5 步：让回答「一个字一个字往外蹦」—— 流式输出。

学到什么：
- Markdown 组件可以先创建为空白，再一点点往里写内容。
- Markdown.get_stream(md)：拿到一个「流写入器」，反复 write() 片段，
  它会自动合并刷新，不会把终端刷爆。
- run_worker()：把耗时的异步任务放到后台跑。
  为什么需要它？如果直接在 on_input_submitted 里 await 流式循环，
  在流结束之前，输入框的按键消息都排不上队，界面就「卡住」了。
- `.stream-pending { display: none; }`：回答首个 chunk 还没来时整行隐藏，
  避免先出现一个没有内容的孤立 `●`；首个 chunk 写入前再显示。

和第 4 步的区别：回答不再一次到位，而是分片流出来。
"""

import asyncio

from rich.text import Text

from textual.app import App, ComposeResult
from textual.widget import Widget
from textual.containers import HorizontalGroup, Vertical, VerticalScroll
from textual.widgets import Input, Markdown, Static

from cjk_wrap import CJKStatic


ANSWER = """\
这是 **Markdown** 渲染的回答：

- 支持列表
- 支持 `行内代码`

```python
print('Hello, Textual!')
```
"""


class UserMessage(CJKStatic):
    """用户消息：✨ 黄色前缀。"""

    DEFAULT_CSS = """
    UserMessage {
        width: 1fr;
        height: auto;
        margin-top: 1;
    }
    """

    def __init__(self, text: str, **kwargs) -> None:
        content = Text.assemble(("✨ ", "yellow"), (text, ""))
        super().__init__(content, **kwargs)


class AssistantMessage(Vertical):
    """AI 消息：● 圆点 + Markdown 回答（初始为空白，等待流式写入）。"""

    DEFAULT_CSS = """
    AssistantMessage {
        width: 1fr;
        height: auto;
    }
    AssistantMessage .stream-pending {
        display: none;
    }
    AssistantMessage .assistant-bullet {
        width: auto;
        height: auto;
        color: #c8cdd5;
        padding: 0 1 0 0;
    }
    AssistantMessage Markdown {
        width: 1fr;
        height: auto;
        padding: 0;
        background: transparent;
    }
    """

    def compose(self) -> ComposeResult:
        with HorizontalGroup(classes="answer-row stream-pending"):
            yield Static("●", classes="assistant-bullet")
            # 注意：这里不再传入 ANSWER，先创建一个空的 Markdown
            yield Markdown(id="answer-md")



class ChatScroll(VerticalScroll):
    """聊天滚动区：修复 anchor() 的一个小 bug。

    anchor() 让滚动区一直吸底；但 Textual 的合成器在「内容不足一屏」时
    会把 scroll_y 直接设成负数（set_reactive 绕过了 0 下限的校验），表现为：
    第一次发消息后，上面的内容整体往下挪、顶部空出一片。
    这里把负的滚动值挡回去即可。
    """

    def set_reactive(self, reactive, value) -> None:
        if (
            isinstance(value, (int, float))
            and value < 0
            and (reactive is Widget.scroll_y or reactive is Widget.scroll_target_y)
        ):
            value = 0
        super().set_reactive(reactive, value)


class ChatApp(App):
    CSS = """
    Screen {
        layout: vertical;
    }
    #chat-scroll {
        width: 1fr;
        height: 1fr;
        padding: 1 2;
    }
    #user-input {
        dock: bottom;
        height: auto;
        padding: 1 2;
    }
    """

    def compose(self) -> ComposeResult:
        with ChatScroll(id="chat-scroll"):
            pass
        yield Input(placeholder="输入问题，按 Enter 发送", id="user-input")

    def on_mount(self) -> None:
        """启动后自动聚焦输入框。"""
        self.query_one("#user-input", Input).focus()

    async def on_input_submitted(self, event: Input.Submitted) -> None:
        user_text = event.value.strip()
        if not user_text:
            return

        self.query_one("#user-input", Input).value = ""

        scroll = self.query_one("#chat-scroll", VerticalScroll)
        await scroll.mount(UserMessage(user_text))
        message = AssistantMessage()
        await scroll.mount(message)

        scroll.anchor()

        # 流式输出放到后台 worker 里跑，界面不会被卡住
        self.run_worker(self.stream_response(message))

    async def stream_response(self, message: AssistantMessage) -> None:
        """模拟 AI 的流式回答：每 0.05 秒吐出 8 个字符。"""
        md = message.query_one("#answer-md", Markdown)
        answer_row = message.query_one(".answer-row")
        stream = Markdown.get_stream(md)
        try:
            for i in range(0, len(ANSWER), 8):
                if i == 0:
                    answer_row.remove_class("stream-pending")
                await stream.write(ANSWER[i : i + 8])
                await asyncio.sleep(0.05)
        finally:
            # 不管中途是否出错，都要把流停掉，否则后台任务不会退出
            await stream.stop()


if __name__ == "__main__":
    app = ChatApp()
    app.run()
````

## 运行与验证

确保已按第 01 章装好环境，然后：

```bash
python steps/step05_streaming.py
```

输入一句话回车，应该看到：

- AI 的 `●` 圆点和回答**同时**出现（不会先有个空圆点）；
- 回答以肉眼可见的速度一段段往外蹦，Markdown 格式（加粗、列表、代码块高亮）逐渐成型；
- 流式过程中你可以继续打字、甚至再按回车发第二条消息，界面不卡——这就是 worker 的意义。

手动验证时重点确认两件事：

- **空回答不显示圆点**：AI 的 `●` 和第一段内容是同时出现的，不会先冒出一个孤零零的空圆点（`answer-row` 的 `stream-pending` 类 + `display: none` 规则在起作用）。
- **流式是逐步写入、不是瞬间完成**：回答是一段段往外蹦的，能看到内容从不完整到完整的过程，最后完整显示 `ANSWER` 里的全部 Markdown 元素（加粗、列表、代码块高亮）。

## 常见问题

- **界面在回答吐完前完全卡死，键盘没反应**：你在 `on_input_submitted` 里直接 `await` 了流式循环，而不是 `run_worker()`。消息处理函数里不能做长耗时 await，会堵住整个消息队列。
- **程序退出时后台还有任务挂着 / 回答偶尔少个尾巴**：漏了 `finally: await stream.stop()`。流写入器必须显式收尾。
- **回答出现之前，屏幕上先闪过一个孤零零的 `●`**：`answer-row` 忘了加 `stream-pending` 类，或者 CSS 里漏了 `display: none` 那条规则。
- **手动运行或截图时颜色全灰**：检查环境变量 `NO_COLOR`。设成 `1` 时 Textual 会进入灰度模式，运行示例前用 `env -u NO_COLOR python steps/step05_streaming.py`（PowerShell：先 `$env:NO_COLOR=""`）。

# 第 06 章：思考过程行（Thinking）

对应文件：`steps/step06_thinking.py`

## 本步目标

上一章回答之前什么都没有。本章在回答之前加一行「思考过程」：灰色圆点 + 灰色斜体文字，逐字出现；思考写完后，回答行才开始流式输出。这正是 Claude Code / Kimi Code CLI 里那种「先想再答」的效果。本步的 thinking 一直展开显示，不折叠。

## 新概念

- **一个组件里的多行结构**：`AssistantMessage` 现在由两行组成——`thinking-row`（灰点 + 思考文本）和 `answer-row`（白点 + Markdown 回答），都是 `HorizontalGroup`，竖着叠在 `Vertical` 里。自定义组件的内部结构可以任意嵌套。
- **`Static.update()`**：原地更新一个 `Static` 组件显示的文本。思考内容是纯文本、逐字增长，用「累积字符串 + `update()`」就够了，不需要动用 Markdown 流。
- **同一个流式技巧用两次**：上一章的「隐藏整行 → 首个内容到达 → `remove_class("stream-pending")`」模式，本章对 thinking 行和 answer 行各用一次。每一行只等自己的第一个字符，互不干扰。
- **用样式区分信息层级**：思考内容用灰色（`#7a8391`）+ 斜体（`text-style: italic`），回答用终端默认前景色（`ansi_default`）。用户一眼就能分出「这是过程」和「这是结果」。`text-style` 是 Textual CSS 的属性，直接写在组件样式里即可。

### 1. 加思考内容常量

文件顶部，`ANSWER` 旁边加一行（`steps/step06_thinking.py:26`）：

```python
THINKING = "Simple greeting, respond in Chinese."
```

真实项目里这会是模型的 reasoning 输出。

### 2. `AssistantMessage`：从一行变两行

上一章 `compose()` 里只有一个 `answer-row`。现在前面再加一个 `thinking-row`（`steps/step06_thinking.py:93`）：

```python
    def compose(self) -> ComposeResult:
        # 第一行：思考过程
        with HorizontalGroup(classes="thinking-row stream-pending"):
            yield Static("●", classes="thinking-bullet")
            yield CJKStatic("", id="thinking-content")
        # 第二行：回答
        with HorizontalGroup(classes="answer-row stream-pending"):
            yield Static("●", classes="assistant-bullet")
            yield Markdown(id="answer-md")
```

注意：

- 两个 row 都带 `stream-pending`——挂载时**两个圆点都不显示**，各自等自己的首个内容。
- 思考正文用 `CJKStatic("")`（就是 `UserMessage` 一直在用的那个修过中文换行的 `Static`），初始为空字符串，等 `update()` 逐字填充。思考内容是纯文本，用不到 `Markdown`。
- 两个圆点用不同的 class（`thinking-bullet` / `assistant-bullet`），因为要上不同的颜色。

### 3. CSS：给 thinking 行上灰色斜体

`DEFAULT_CSS` 里加两条规则（上一章的 `.stream-pending`、`.assistant-bullet`、`Markdown` 规则原样保留）：

```css
    AssistantMessage .thinking-bullet {
        width: auto;
        height: auto;
        color: #7a8391;
        padding: 0 1 0 0;
    }
    AssistantMessage #thinking-content {
        width: 1fr;
        height: auto;
        color: #7a8391;
        text-style: italic;
    }
```

和回答行的样式对照着看：结构完全一样（圆点 `width: auto`，正文 `width: 1fr`），只是颜色从终端默认前景 `ansi_default` 换成更暗的 `#7a8391`，正文多一个 `text-style: italic`。视觉上的「轻」就是这么来的。

### 4. `stream_response`：先逐字思考，再流式回答

上一章这个方法只有「流式写回答」一段。现在在它前面加「逐字写思考」一段（`steps/step06_thinking.py:166`）：

```python
    async def stream_response(self, message: AssistantMessage) -> None:
        """先逐字写出思考过程，再流式输出回答。"""
        # 第一步：思考内容逐字出现（每 0.02 秒一个字）
        thinking_content = message.query_one("#thinking-content", Static)
        thinking_row = message.query_one(".thinking-row")
        buffer = ""
        for char in THINKING:
            if not buffer:
                thinking_row.remove_class("stream-pending")
            buffer += char
            thinking_content.update(buffer)
            await asyncio.sleep(0.02)

        # 第二步：回答流式输出
        md = message.query_one("#answer-md", Markdown)
        answer_row = message.query_one(".answer-row")
        stream = Markdown.get_stream(md)
        try:
            for i in range(0, len(ANSWER), 8):
                if i == 0:
                    answer_row.remove_class("stream-pending")
                await stream.write(ANSWER[i : i + 8])
                await asyncio.sleep(0.05)
        finally:
            await stream.stop()
```

第一段逐段看：

- `buffer` 累积已经到达的字符；`if not buffer` 在**第一个字符**落进 buffer 之前成立，正好用来移除 thinking 行的 `stream-pending`——灰点出现的同一刻，后面已经有第一个字了。
- `thinking_content.update(buffer)` 每次把整段已累积文本刷进组件。纯文本逐字场景，这比 Markdown 流简单直接。
- 思考循环结束后才进入第二段回答流。两段是严格顺序的：思考不写完，回答的圆点不会出现。

`on_input_submitted` 不用改——它还是 `run_worker(self.stream_response(message))`，只是这个方法的内部变长了。

## 完整代码

下面是 `steps/step06_thinking.py` 的完整源码，和仓库里的文件逐字一致。你也可以直接运行仓库里的文件对照。

````python
"""第 6 步：给 AI 消息加上「思考过程」行（Thinking）。

学到什么：
- 一个组件里可以有多行结构：AssistantMessage 现在是两行 ——
  thinking-row（灰点 + 思考内容）和 answer-row（白点 + Markdown 回答）。
- 同一个流式技巧用两次：先把思考内容逐字写出来，再流式输出回答。
- thinking-row 和 answer-row 初始带 `stream-pending`（`display: none`）：
  每一行都等自己的首个字符到达才显示，所以不会提前出现空的 `●`。
- 用 Text 的 style 参数控制颜色 + 斜体，让思考内容看起来「轻」一点。

和第 5 步的区别：回答之前，先有一行灰色斜体的思考过程。
"""

import asyncio

from rich.text import Text

from textual.app import App, ComposeResult
from textual.widget import Widget
from textual.containers import HorizontalGroup, Vertical, VerticalScroll
from textual.widgets import Input, Markdown, Static

from cjk_wrap import CJKStatic


THINKING = "Simple greeting, respond in Chinese."

ANSWER = """\
这是 **Markdown** 渲染的回答：

- 支持列表
- 支持 `行内代码`

```python
print('Hello, Textual!')
```
"""


class UserMessage(CJKStatic):
    """用户消息：✨ 黄色前缀。"""

    DEFAULT_CSS = """
    UserMessage {
        width: 1fr;
        height: auto;
        margin-top: 1;
    }
    """

    def __init__(self, text: str, **kwargs) -> None:
        content = Text.assemble(("✨ ", "yellow"), (text, ""))
        super().__init__(content, **kwargs)


class AssistantMessage(Vertical):
    """AI 消息：第一行思考过程（灰点 + 灰斜体），第二行回答（白点 + Markdown）。"""

    DEFAULT_CSS = """
    AssistantMessage {
        width: 1fr;
        height: auto;
    }
    AssistantMessage .stream-pending {
        display: none;
    }
    AssistantMessage .thinking-bullet {
        width: auto;
        height: auto;
        color: #7a8391;
        padding: 0 1 0 0;
    }
    AssistantMessage #thinking-content {
        width: 1fr;
        height: auto;
        color: #7a8391;
        text-style: italic;
    }
    AssistantMessage .assistant-bullet {
        width: auto;
        height: auto;
        color: ansi_default;
        padding: 0 1 0 0;
    }
    AssistantMessage Markdown {
        width: 1fr;
        height: auto;
        padding: 0;
        background: transparent;
    }
    """

    def compose(self) -> ComposeResult:
        # 第一行：思考过程
        with HorizontalGroup(classes="thinking-row stream-pending"):
            yield Static("●", classes="thinking-bullet")
            yield CJKStatic("", id="thinking-content")
        # 第二行：回答
        with HorizontalGroup(classes="answer-row stream-pending"):
            yield Static("●", classes="assistant-bullet")
            yield Markdown(id="answer-md")



class ChatScroll(VerticalScroll):
    """聊天滚动区：修复 anchor() 的一个小 bug。

    anchor() 让滚动区一直吸底；但 Textual 的合成器在「内容不足一屏」时
    会把 scroll_y 直接设成负数（set_reactive 绕过了 0 下限的校验），表现为：
    第一次发消息后，上面的内容整体往下挪、顶部空出一片。
    这里把负的滚动值挡回去即可。
    """

    def set_reactive(self, reactive, value) -> None:
        if (
            isinstance(value, (int, float))
            and value < 0
            and (reactive is Widget.scroll_y or reactive is Widget.scroll_target_y)
        ):
            value = 0
        super().set_reactive(reactive, value)


class ChatApp(App):
    CSS = """
    Screen {
        layout: vertical;
    }
    #chat-scroll {
        width: 1fr;
        height: 1fr;
        padding: 1 2;
    }
    #user-input {
        dock: bottom;
        height: auto;
        padding: 1 2;
    }
    """

    def compose(self) -> ComposeResult:
        with ChatScroll(id="chat-scroll"):
            pass
        yield Input(placeholder="输入问题，按 Enter 发送", id="user-input")

    def on_mount(self) -> None:
        """启动后自动聚焦输入框。"""
        self.query_one("#user-input", Input).focus()

    async def on_input_submitted(self, event: Input.Submitted) -> None:
        user_text = event.value.strip()
        if not user_text:
            return

        self.query_one("#user-input", Input).value = ""

        scroll = self.query_one("#chat-scroll", VerticalScroll)
        await scroll.mount(UserMessage(user_text))
        message = AssistantMessage()
        await scroll.mount(message)

        scroll.anchor()

        self.run_worker(self.stream_response(message))

    async def stream_response(self, message: AssistantMessage) -> None:
        """先逐字写出思考过程，再流式输出回答。"""
        # 第一步：思考内容逐字出现（每 0.02 秒一个字）
        thinking_content = message.query_one("#thinking-content", Static)
        thinking_row = message.query_one(".thinking-row")
        buffer = ""
        for char in THINKING:
            if not buffer:
                thinking_row.remove_class("stream-pending")
            buffer += char
            thinking_content.update(buffer)
            await asyncio.sleep(0.02)

        # 第二步：回答流式输出
        md = message.query_one("#answer-md", Markdown)
        answer_row = message.query_one(".answer-row")
        stream = Markdown.get_stream(md)
        try:
            for i in range(0, len(ANSWER), 8):
                if i == 0:
                    answer_row.remove_class("stream-pending")
                await stream.write(ANSWER[i : i + 8])
                await asyncio.sleep(0.05)
        finally:
            await stream.stop()


if __name__ == "__main__":
    app = ChatApp()
    app.run()
````

## 运行与验证

确保已按第 01 章装好环境，然后：

```bash
python steps/step06_thinking.py
```

输入一句话回车，应该看到这个顺序：

1. 灰色 `●` 和灰色斜体的 `Simple greeting, respond in Chinese.` 逐字出现；
2. 思考写完后，亮色 `●` 出现，Markdown 回答开始流式蹦字（和上一章一样）；
3. 两行都留在屏幕上，thinking 不折叠、不消失。

可以连发几条消息，确认每条的「先想后答」顺序都正确，滚动吸底正常。

手动验证时重点确认两件事：

- **两行按各自的节奏出现，顺序严格**：发消息后先只有 thinking 行（灰色斜体逐字出现），此时回答行还完全看不到；思考写完后回答行才显示。不会「两行一起出现」或「回答先于思考」。
- **内容完整、顺序正确**：流跑完后，thinking 文本完整（对照「完整代码」里的 `THINKING` 常量）、Markdown 回答完整（对照 `ANSWER`），并且 thinking 行始终排在回答行上面。

## 常见问题

- **思考内容想用 `Markdown` 的流来写**：可以，但没必要。思考是纯文本逐字到达，`Static.update(buffer)` 两行就搞定；Markdown 流是为「带格式的结构化内容」准备的，留给回答用。工具按内容形态选，不是越高级越好。
- **回答的圆点在思考还没写完时就出现了**：两段共用一个 `stream-pending` 移除时机了。检查代码：thinking 行在 `if not buffer`（首字符）时移除，answer 行在 `i == 0`（首片）时移除，两个判断缺一不可。
- **想让 thinking 像真实 CLI 那样答完后折叠成一行摘要**：本步特意不折叠（docstring 里也写明了），保持结构简单。折叠需要自己加状态（展开/收起）和按键处理，可以作为练手扩展；仓库 `_archive/` 里的成品有完整实现可参考。
